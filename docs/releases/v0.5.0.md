# SMAD v0.5.0 — Markdown source-line highlights

Rendered Markdown now accepts `md://...?highlight=...` source ranges:

```sh
smad-axi open 'md://./plan.md?highlight=12-24,48'
```

- Paragraphs, lists and quotations highlight only text originating on the requested source lines, even when lines merge or wrap. Formatting, decoded entities, Unicode, CRLF and normalized multiline inline code retain provenance.
- Code highlights exact source lines, including indented and list-nested blocks. Blank rendered code lines lack visible markers and explicitly warn.
- Tables highlight selected rows. Mermaid and image source spans select their complete native widgets. Failed diagrams keep exact source-code fallback mapping.
- Native controls apply, navigate and clear ranges. Ranges persist with documents, rebuild after atomic saves and remain absolute line coordinates rather than following moved text. Heading fragments retain scroll precedence.
- Invisible syntax and unsupported transformations are reported honestly: visible diagnostics and AXI `ready_with_warnings`, not neighbouring/block guesses.
- Additive protocol-v2 capability `markdown_source_ranges_v1` prevents false success against older servers; capable-server opens verify request identity to detect supersession.

## Boundaries

No HTML/WebKit fallback, editing, patch application or `diff://` scheme. Existing code/comparison and Lavish review behavior remains separate. This does not add math, footnotes or full GFM conformance. Reference definitions, ordinary code fences, table separators, setext underlines and blank source lines may have no visible counterpart.

Markdown is bounded to 1 MiB, 20,000 source lines and 20,000 parser events. Source-range limits remain 64 ranges / 2,048 input bytes / coordinate 1,000,000. Tag applications are coalesced; only the first 16 unmapped coordinates are reported. Existing table/image/Mermaid budgets remain unchanged.

## Validation

Workspace, protocol/URI, capability/supersession and persistence checks; isolated GTK mapping tests for exact text/widget selection, clearing, blank code, Unicode/CRLF, fallback diagnostics and atomic-save remapping; existing full native/comparison/application gates including no WebKit descendants before review and HerdR no-raise behavior. Downloaded release artifacts are checked separately before installation.

Checkpoint state/snapshots before upgrading. Restart the persistent server and sole sync owner to use the new capability; installing files alone leaves an older server running.

# SMAD v0.6.2

## Local review routing with Tailscale-enabled Lavish

- Open local Lavish reviews even when upstream advertises a phone-ready Tailscale hostname rather than a loopback URL.
- Both `smad-axi open lavish://…` and the compatibility `lavish-open` launcher route advertised non-loopback hosts through Lavish’s same-port `127.0.0.1` listener. Preserve the scheme, port, session path, query and fragment; existing loopback URLs stay unchanged.
- Never resolve or connect to the advertised remote hostname. Raw browser-control submissions still reject remote hosts; scheme, credential and session-path restrictions remain enforced.
- Keep upstream arguments, `--no-open`, original compatibility-launcher output, source-file checks and user-ended-session behavior intact. No Tailscale reconfiguration or running review-server restart is required for this fix.

Regression coverage includes both launchers, unsafe URLs, and an isolated GTK/WebKit application test that opens an unresolvable advertised hostname locally while rejecting the same URL through raw browser control.

No protocol or persistence migration. This is a launcher-side fix and does not require restarting an already-running compatible SMAD browser.

# SMAD v0.3.0 — Show Me Agent Document

Lavish Browser is now **SMAD**, a persistent native desktop surface for agent documents.

## New

- **`smad-axi`**: an AXI-style CLI with official TOON output, JSON mode, read-only live state,
  compact counts, structured errors, contextual help and verified document readiness.
- **Explicit renderer schemes**: `md://` for native Markdown and `lavish://` for existing
  upstream Lavish/WebKit reviews. Relative paths resolve from the invoking directory.
- **Native Markdown**: highlighted code, aligned rich GTK tables, local images, heading links,
  continuous document copy (including TSV table data), and atomic-save-aware live updates.
- **Native Mermaid**: background Merman SVG rendering, bounded work/cache, cancellation of
  superseded revisions, selectable source, and visible diagnostics. Failed diagrams are exposed
  by AXI as `ready_with_warnings`, not silently presented as fully successful renders.
- **Stable project grouping**: captured HerdR/Zellij identity, duplicate reuse, persistent metadata,
  and no-start/no-raise lifecycle synchronization.

```zsh
smad-axi open md://./README.md
smad-axi open 'md:///absolute/path/plan.md#next-steps'
smad-axi open lavish://./review.html
smad-axi status --json
```

## Downloads

- `smad-x86_64-linux.tar.gz`: complete installation bundle (recommended), including `smad`,
  `smad-axi`, integrations, compatibility launchers, desktop metadata, skill and attribution.
- `smad-server-x86_64-linux`: standalone GUI/server binary; install as `smad`.
- `smad-axi-x86_64-linux`: standalone CLI; install as `smad-axi` beside the server.
- `smad-third-party-notices.tar.gz`: attribution and covered dependency source for standalone users.
- `SHA256SUMS`: checksums of all published artifacts.

Linux x86-64, Ubuntu 24.04-compatible ABI, GTK 4.10+, WebKitGTK 6 and a native SVG loader are
required for the server. Native Markdown requires no Node/browser runtime. `lavish://` requires
`npx` and upstream `lavish-axi`. NixOS installations must package/patchelf against Nix libraries.
Pop!_OS installations should wrap the canonical `smad` binary to clear conflicting inherited
nixGL/Mesa paths, as with the prior browser launcher.

## Migration

SMAD imports legacy browser metadata only when its new state file is absent. Writes go to
`~/.local/state/smad/state.json`; the original `lavish-browser/state.json` is left untouched.
The application ID and default socket are new. Legacy launcher/helper aliases remain in the
bundle, but new automation should use `smad-axi`. Installation does not restart the running
legacy browser or alter agent hooks. Update the lifecycle service to the new package when ready.

## Verification and known limits

Workspace tests, warning-denied Clippy, formatting and the WASI plugin build are required by the
release pipeline. Isolated GTK/application tests cover highlighting, table layout/copy, common
Mermaid families, malformed diagrams, cancellation, live updates/recovery, scroll retention,
project identity, AXI opens/warnings and the existing WebKit review surface.

This is not full GFM/Mermaid.js parity. ELK/math Mermaid features are excluded; unsupported
capabilities produce diagnostics. Unknown/over-budget code highlighting falls back to plain
text. Remote images, an editor, diagram zoom/editing, footnotes and math are not implemented.
The full upstream manual whiteboard/export compatibility gate is separate from these checks.
See `docs/native-markdown.md` for precise resource limits and evidence paths.

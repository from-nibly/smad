# SMAD v0.4.0 — whole source files and full-file comparisons

## New

- `code://` opens complete UTF-8 source files natively, with syntax highlighting,
  original line numbers, selectable text and live updates. The gutter is not copied.
- `?highlight=12-24,48,70-85` adds bounded, normalized source-coordinate overlays.
  Amber gutter marks/underlines remain distinct from syntax, diff colors and selection;
  previous/next and Clear controls are available.
- `smad-axi compare FILE --base REV` pins an exact base and watches the working tree.
  `--base REV --head REV` captures two exact snapshots; optional `--merge-base` is explicit.
  `--old FILE --new FILE` captures file snapshots; `/dev/null` explicitly denotes absence.
- Unified comparisons retain **all unchanged context and deleted lines**, with old/new
  numbering and change navigation. `--highlight` uses new-side coordinates;
  `--highlight-old` uses old-side coordinates. No `diff://` scheme, editing or patch apply.
- Renderer-aware identity allows Markdown/code/comparison views of one file to coexist
  without duplicate same-renderer entries. Legacy selection metadata is migrated.
- Immutable, content-addressed snapshots survive CLI exit and branch/source changes.
  Live reloads retain the base, handle atomic saves, preserve approximate scroll and
  retain the last good display on errors. Git inputs use bounded, shell-free commands.
- Source syntax palettes are adjusted for light/dark contrast, including diff backgrounds.
  The desktop URI handler and shipped agent skill include the new workflows.

## Validation

Workspace formatting, warning-denied Clippy, protocol/core/migration/Git tests and WASI
build; private-display native GUI tests and actual AXI application smoke. GUI evidence
covers Unicode offsets, ranges/navigation/clear, independent old/new numbering, full
context, atomic updates, pinned base, scroll, deletion/recovery and cleanup. Tests also
check native-only operation without any WebKit child and existing Markdown/Lavish/HerdR
behavior. Release CI additionally builds optimized binaries and packages third-party notices.

## Limits and upgrade notes

- Whole accepted inputs are shown, never truncated patches. Files are limited to 1 MiB /
  20,000 lines each. Oversized syntax work falls back to plain text with warnings; comparison
  work has an explicit bound. Unknown languages render plain text.
- Unified view only; no side-by-side, inline word diff or move detection. Git symlink and
  submodule comparisons are unsupported. CRLF is displayed/copied as LF; final-newline
  differences are retained in comparison semantics and reported.
- Markdown **source-line** overlays are deferred and explicitly rejected. Existing Markdown
  heading links, tables and Mermaid rendering remain available.
- Snapshot storage is bounded to 128 MiB / 4,096 entries and is not automatically pruned.
  Preserve `smad/snapshots` together with `smad/state.json`. Missing/corrupt snapshots fail
  visibly. Older binaries cannot read the new document kinds: checkpoint state before
  upgrading/downgrading; do not point an old binary at new state.
- Running servers advertise native-source capability. The CLI asks for an upgrade/restart
  when the active server is too old; installation alone does not restart it.

See [native source documentation](https://github.com/from-nibly/smad/blob/v0.4.0/docs/native-source.md)
for exact CLI semantics, resource bounds and remaining limitations.

Linux x86-64 bundle `smad-x86_64-linux.tar.gz`, standalone `smad-server-x86_64-linux`
and `smad-axi-x86_64-linux`, `smad-third-party-notices.tar.gz`, and `SHA256SUMS`.
